## 一、必须先修的 P0 问题（阻塞后续一切）

### 1.1 🔴 提交现有未提交改动

线上运行的代码（反馈功能）在 git 中不存在。一旦工作区丢失无法回滚。

```
→ git add -A && git commit -m "feat: 用户反馈系统 + 死链一键清理 + 模板转义检查"
```

### 1.2 🔴 健康检查不可靠 — 不要把概率性信号接到不可逆动作上

**现状**：`health.js` 用 `HEAD` 方法检查 URL。HEAD 失败 → `deadurls.js` 自动 `UPDATE sites SET enabled = 0` → 首页消失。无需管理员确认。

**问题**：
- HEAD 不被支持的站点（如 AgentRouter 的 `/register?aff=l1gl` 路径）会被判死
- 403（WAF/Cloudflare 挑战）、405、429 等"活着"的状态码会被判死
- 单次网络抖动即可导致高价值站点静默下线

**修法（3 件事一起做）**：

| 改动 | 文件 | 说明 |
|------|------|------|
| HEAD 失败时 fallback GET | `health.js:21-28` | HEAD 抛错或返回 ≥400 时，重试一次 `GET` + `Range: bytes=0-0`（只对失败 URL 触发） |
| 放宽存活判定 | `health.js:31` | `403/405/429/501` 视为存活（能回状态码 = 服务器在） |
| 移除自动下线 | `deadurls.js:35` + `index.js:528,559` | `addDeadUrl` 不再联动 `enabled=0`；前端 `action:"add"` 改为列出结果由管理员勾选确认，或改为"连续 3 次检测失败才停用" |

### 1.3 🔴 改名/删除站点会产生孤儿反馈

`feedbacks` 表用 `site_name` 关联站点。改名时 `sites.js:240-256` 的 batch 同步了 `votes` 但**漏了 feedbacks**。删除时 `sites.js:296-300` 同步了 `votes` 和 `dead_urls` 但**也漏了 feedbacks**。

**修法**：

```js
// sites.js 改名 batch 中追加一条：
db.prepare("UPDATE feedbacks SET site_name = ? WHERE site_name = ?").bind(updated.name, siteName),

// sites.js 删除路径中追加一条：
await dbRun(db, "DELETE FROM feedbacks WHERE site_name = ?", [siteName]);
```

### 2.1 submissions.js 限流 bug

`created_at > epoch毫秒字符串` 恒为真（SQLite 字典序 "2026..." > "1756..."），导致所有历史提交都被计入限流，5 次额度永久用完不恢复。

**修法**：照抄 `feedbacks.js:47` 的正确写法：

```js
// 改前（错误）：
[ip, (now - SUBMIT_RATE_WINDOW_MS).toString()]

// 改后（正确）：
[ip, Math.floor((now - SUBMIT_RATE_WINDOW_MS) / 1000)]
// SQL: created_at > datetime(?, 'unixepoch')
```

### 2.2 feedbacks.type CHECK 约束

当前 `CHECK(type IN ('error','correction','positive'))`，docs/09 阶段 D 要新增 `still_works`/`dead`。SQLite 不支持 ALTER CHECK，必须重建表。

**推荐方案**：趁表空做一次 migration，把 5 个 type 一次加齐：

```sql
-- 0003_fix_feedbacks_type.sql
CREATE TABLE feedbacks_new AS SELECT * FROM feedbacks;
DROP TABLE feedbacks;
CREATE TABLE feedbacks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  site_name TEXT NOT NULL,
  type TEXT NOT NULL CHECK(type IN ('error','correction','positive','still_works','dead')),
  content TEXT NOT NULL DEFAULT '',
  ip TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL DEFAULT 'new' CHECK(status IN ('new','read','resolved')),
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
INSERT INTO feedbacks SELECT * FROM feedbacks_new;
DROP TABLE feedbacks_new;
-- 重建索引
CREATE INDEX IF NOT EXISTS idx_feedbacks_site ON feedbacks(site_name);
CREATE INDEX IF NOT EXISTS idx_feedbacks_status ON feedbacks(status);
CREATE INDEX IF NOT EXISTS idx_feedbacks_created ON feedbacks(created_at);
```

### 2.3 合并重复的健康检查实现

`batchCheckUrls()`（链接健康 tab）和 `sitesCleanupDeadLinks()`（站点管理 tab）做的是完全相同的事，但用了两份不同的代码（一份 `const`/箭头函数，一份 `var`/`function`）。

**修法**：抽一个 `runHealthScan({ onProgress, onResult })` 函数，两个按钮都调它。

### 2.4 switchTab 依赖 DOM 顺序

```js
// 现在（脆弱）：
var tabs = ["sites","submissions","health","feedback","schema"];
document.querySelectorAll(".tab-btn").forEach((btn, i) => { btn.classList.toggle("active", tabs[i] === tab); });

// 改后（健壮）：
document.querySelectorAll(".tab-btn").forEach(btn => { btn.classList.toggle("active", btn.dataset.tab === tab); });
```

## 三、阶段 A：数据结构化（2~3 天）

### 3.1 DDL — 0003_struct_fields.sql

```sql
-- 新增字段
ALTER TABLE sites ADD COLUMN slug TEXT NOT NULL DEFAULT '';
ALTER TABLE sites ADD COLUMN kind TEXT NOT NULL DEFAULT 'api_site';
ALTER TABLE sites ADD COLUMN quota_min REAL;
ALTER TABLE sites ADD COLUMN quota_max REAL;
ALTER TABLE sites ADD COLUMN quota_unit TEXT;
ALTER TABLE sites ADD COLUMN quota_period TEXT;
ALTER TABLE sites ADD COLUMN quota_calls_est INTEGER;
ALTER TABLE sites ADD COLUMN quota_tier TEXT;
ALTER TABLE sites ADD COLUMN quota_raw TEXT;
ALTER TABLE sites ADD COLUMN needs_proxy INTEGER DEFAULT 0;
ALTER TABLE sites ADD COLUMN verified_at TEXT;
ALTER TABLE sites ADD COLUMN verified_by TEXT;

-- 唯一索引（slug 允许 NULL 但设计意图要求非空，DEFAULT '' 已确保）
CREATE UNIQUE INDEX IF NOT EXISTS idx_sites_slug ON sites(slug);
CREATE INDEX IF NOT EXISTS idx_sites_verified ON sites(verified_at);
CREATE INDEX IF NOT EXISTS idx_sites_tier ON sites(quota_tier);
```

**⚠️ D1 ALTER TABLE 不可逆**：新增列后无法删除（SQLite 限制）。字段设计有误只能加新列修正，旧列永久存在。执行前务必导出 D1 快照：`wrangler d1 execute SKFREE_DB --remote --command ".dump" > backup.sql`

`sites.js:96` 的 `.filter((s) => !deadUrlSet.has(s.url))` 改为输出 `dead: true` 标记，让前端决定展示策略（折叠到列表底部或降饱和显示）。

## 四、阶段 B：信息架构重构（3~4 天）

### 4.1 默认视图：对比表

18 条数据的"选最优"任务适合表格（一屏全可见、点列头排序），不适合卡片网格（首屏只看 6 条）。保留卡片视图作为切换选项，移动端默认卡片。

### 4.2 筛选器：三层

```
第一层：快捷视图（今天能签到 / 高额度 / 免费生图 / 无需魔法 / 一次性限免）
第二层：搜索 + 精确条件（额度档位 / 能力 / 门槛 / 类型 / 验证状态）
第三层：结果条 + 排序 + 视图切换
```

### 4.3 URL 状态同步

`URLSearchParams` + `history.replaceState`（筛选变化 replace，预设切换 push）。URL 可分享、可收藏、浏览器前进后退可用。

### 4.4 鲜度可视化

`verified_at` 色阶：🟢 ≤24h / 🟡 ≤7d / ⚪ >7d / ⚫ 未验证。死链标记为"已失效"显示在列表底部，不隐藏。

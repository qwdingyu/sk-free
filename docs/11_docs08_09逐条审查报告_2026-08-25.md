### 1.1 需要修正的错误

#### ❌ 错误 1：总代码行数 "9,551行" 不准确

文档声称总代码 9,551 行。实测：

| 文件范围 | 行数 |
|----------|------|

**建议修改**：改为"约 7,100 行 main code + 约 1,100 行辅助脚本/配置，合计约 8,200 行"，或者直接去掉精确行数，保留"代码/数据比约 400:1"。

**影响**：不影响结论（仍然严重过度工程），但数字不准确会让读者质疑审计的严谨性。

## 三、两份文档共同的问题

### 3.1 行号引用系统性偏移

docs/08 和 docs/09 共引用了约 30 个具体的 `app.js:XXX` / `sites.js:XXX` 行号。经逐一验证：

| 精确度 | 数量 | 占比 |
|--------|------|------|
| 完全匹配（±2 行） | 11 | 37% |
| 偏移 3-10 行 | 13 | 43% |
| 偏移 10+ 行或指向错误函数 | 6 | 20% |

**原因推测**：文档编写时的代码版本与当前版本不同（中间经历了多次 commit，行号会漂移）。这不是文档"写错了"，而是**代码迭代后文档未同步更新行号**。

**影响**：如果有人按行号去定位代码，约 20% 的情况会找错位置。但这不影响技术判断的正确性。

**建议**：后续文档引用代码时优先用**函数名 + 关键语句**（如 "`makeCheckinBadge` 中的 `badge.textContent = \`${label} 刀\``"），而不是纯行号。行号随代码变动，函数名不会。

### 3.2 缺少的风险评估

两份文档都聚焦于"做什么"和"怎么做"，但缺少以下关键风险评估：

| 风险 | 说明 |
|------|------|
| D1 ALTER TABLE 的不可逆性 | 新增列后无法删除（SQLite 限制）。如果字段设计有误，只能加新列修正，旧列永久存在。docs/09 的迁移方案应标注此约束 |
| broadcast-html.js 自动构建的转义风险 | build-html.js 引入新单点故障：如果转义逻辑有 bug，会批量损坏线上前端。建议构建后自动运行 check-template-escapes.js |
| 前端模块拆分后的调试体验 | 拼接后的代码没有 source map，报错行号是拼接后的行号。需要 build 脚本输出行号映射 |
| 18 条数据的"黄金数据"风险 | 如果 backfill 填错了（比如 needs_proxy 误判），直接影响用户决策。docs/09 说"宁可留空"是正确的 |

# 02 投票系统设计方案

> 日期：2026-08-24
> 状态：待实施

## 一、设计目标

为 sk-free 公益 API 站点导航增加社区投票功能（👍/👎），让用户可以对站点进行评价，形成社区共识排名。

## 二、设计原则

1. **不破坏现有部署模式**：GitHub Pages 纯静态 + Cloudflare Workers 轻量 API
2. **零依赖**：前端继续使用 vanilla JS，无框架引入
3. **独立于 GitHub 仓库**：投票数据存储在 Cloudflare KV，不污染 sites.json
4. **优雅降级**：API 不可用时，站点列表正常显示，仅隐藏投票区域
5. **防刷优先**：IP 级速率限制 + localStorage 前端校验双重保障

## 三、架构设计

```
┌─────────────────────────────────────────────────┐
│                  用户浏览器                       │
│                                                   │
│  sites.json ──→ 静态渲染站点卡片                   │
│                                                   │
│  Worker API ──→ 合并投票数据 ──→ 渲染投票按钮      │
│  (KV)              ↓                              │
│              localStorage                        │
│              (个人投票记录)                        │
└──────────┬──────────────────────┬────────────────┘
           │                      │
           ▼                      ▼
┌─────────────────┐   ┌──────────────────────────┐
│  GitHub Pages   │   │  Cloudflare Workers KV   │
│  (纯静态)       │   │  (投票 API)              │
│                 │   │                            │
│  sites.json     │   │  votes.json   — 投票计数   │
│  styles.css     │   │  rate_limits  — 速率限制   │
│  app.js         │   │                            │
└─────────────────┘   └──────────────────────────┘
```

## 四、数据流

### 4.1 页面加载

```
1. fetch sites.json        → 渲染站点卡片（立即可见）
2. fetch Worker /api/votes  → 合并投票数据，更新投票按钮
3. 读取 localStorage       → 标记个人已投票状态
```

### 4.2 用户投票

```
1. 前端校验：localStorage 是否已投票 → 是：提示"已投票"
2. 发送 POST /api/vote    → Worker 校验 + 速率限制
3. 成功：更新本地状态 + localStorage 记录
4. 失败（429）：提示冷却时间
```

## 五、Worker API 设计

### 5.1 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/votes` | 返回所有站点投票数据 |
| POST | `/api/vote` | 提交单次投票 |
| GET | `/api/health` | 健康检查 |

### 5.2 GET /api/votes

**响应：**
```json
{
  "ok": true,
  "votes": {
    "站点名A": { "up": 12, "down": 3 },
    "站点名B": { "up": 5, "down": 1 }
  }
}
```

### 5.3 POST /api/vote

**请求：**
```json
{
  "site": "站点名",
  "vote": "up"    // "up" | "down"
}
```

**成功响应：**
```json
{
  "ok": true,
  "votes": { "up": 13, "down": 3 }
}
```

**错误响应：**
```json
{
  "ok": false,
  "error": "投票过于频繁，请 45 分钟后再试"
}
```

### 5.4 存储方案

**KV Key: `votes.json`**
```json
{
  "站点名A": { "up": 12, "down": 3 },
  "站点名B": { "up": 5, "down": 1 }
}
```

选择全量 blob 而非 per-site key 的原因：
- 68 个站点 × ~20 bytes ≈ 1.4KB，远低于 KV 单值限制（25MB）
- 一次请求获取所有投票数据，减少 Worker 调用次数
- KV 的最终一致性对投票场景完全可接受

**KV Key: `rate_limits`**
```json
{
  "站点名A": { "1.2.3.4": 1692844800000 },
  "站点名B": { "5.6.7.8": 1692844800000 }
}
```

### 5.5 防刷策略

| 层级 | 机制 | 说明 |
|------|------|------|
| 前端 | localStorage 记录 | 同一浏览器对同站点只能投一次 |
| Worker | IP 速率限制 | 同一 IP 对同站点每小时最多 1 次投票 |
| Worker | 参数校验 | 校验 site/vote 参数合法性 |
| Worker | CORS 白名单 | 仅允许指定前端域名访问 |

## 六、前端设计

### 6.1 卡片模板变更

在现有卡片模板的 `card-head` 区域增加投票按钮组：

```html
<div class="vote-bar">
  <button class="vote-btn vote-up" data-vote="up" aria-label="支持">👍</button>
  <span class="vote-score">0</span>
  <button class="vote-btn vote-down" data-vote="down" aria-label="不推荐">👎</button>
</div>
```

### 6.2 视觉设计

- 投票按钮组：紧凑水平排列，位于卡片头部右侧
- 投票得分：`👍数 - 👎数`，正数绿色，负数红色，零灰色
- 已投票状态：按钮高亮 + 轻微放大，提示"已投票"
- 交互反馈：点击后立即更新（乐观更新），无需等待 API 响应

### 6.3 排序功能

工具栏增加排序选择器：

```
[搜索框] [收录 68 | 可签到 45 | 可生图 12] [排序 ▾]
```

排序选项：
- 默认（sites.json 原始顺序）
- 按评分排序（高→低）

### 6.4 优雅降级

```javascript
// Worker API 不可用时：隐藏投票区域，站点列表正常显示
if (!voteDataLoaded) {
  document.querySelectorAll(".vote-bar").forEach(el => el.hidden = true);
}
```

## 七、技术选型对比

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| Cloudflare Workers + KV | 轻量、无服务器、免费额度充足 | 需要 Cloudflare 账号 | ✅ **采用** |
| GitHub Issues 打分 | 零后端 | 无法自动化、UX 差 | ❌ |
| Google Forms | 简单 | 外部依赖、数据不互通 | ❌ |
| JSON in repo | 无后端 | 用户无法直接打分、PR 冲突 | ❌ |
| Supabase/Firebase | 功能丰富 | 过重、需注册、有费用 | ❌ |

## 八、部署流程

### 首次部署

```bash
# 1. 创建 KV 命名空间
cd worker/
npx wrangler login
npx wrangler kv:namespace create SKFREE_KV
# 将输出的 ID 填入 wrangler.toml

# 2. 部署 Worker
npx wrangler deploy

# 3. 更新 app.js 中的 VOTE_API_URL
# 改为实际的 Worker 地址（如 https://sk-free-vote.xxx.workers.dev）

# 4. 提交前端代码
cd ..
git add -A && git commit -m "feat: add vote system"
git push deploy main
```

### 日常部署

```bash
# 一键部署（推荐）
bash deploy.sh --worker

# 仅更新站点数据
bash deploy.sh
```

## 九、成本估算

| 资源 | 免费额度 | 预计用量 |
|------|----------|----------|
| Cloudflare Workers | 100,000 请求/天 | ~200 请求/天 |
| Cloudflare KV 读取 | 100,000 次/天 | ~200 次/天 |
| Cloudflare KV 写入 | 1,000 次/天 | ~100 次/天 |
| Cloudflare KV 存储 | 1 GB | < 10 KB |

**结论：完全在免费额度内，无需任何费用。**

# 16 · 死链库独立化与导入感知 Phase 1 方案

> 日期：2026-08-27　状态：已批准实施
> 本文是 Phase 1 的唯一执行依据；未批准前不执行 Phase 2。

## 一、问题定义

dead_urls 表名义上是"死链库"，但 sites.js 在站点恢复/启用时主动删除它（4 处 DELETE），导致：

1. 站点恢复 → dead_urls 被删 → "历史上已死"证据丢失
2. 重新导入同一 JSON → 系统看不到历史 → 重建启用站点
3. 管理员不得不再次手动标记死链 → 循环

**根因**：dead_urls 同时扮演"证据库"和"黑名单"两种角色，且被站点状态变更随意清理。

## 二、设计原则（不变）

- dead_urls = 已知死链证据库（append-only）
- sites.enabled = 当前状态轴（唯一状态入口）
- 导入、删除、手动标记三处都引用 dead_urls，但**没有任何一处自动改 enabled**
- 用户在导入预览里看到"已知死链"标记，自己决定怎么处理

## 三、Phase 1 变更清单（最小可批准）

### 3.1 sites.js：恢复/启用站点时不再清理 dead_urls

**删除两处代码**：
- `worker/src/sites.js` handleAdminUpdateSite 恢复站点时的 dead_urls 清理（原 line 530 附近）
- `worker/src/sites.js` 批量启用时的 dead_urls 清理（原 line 630 附近）

**保留**：
- 单站删除（原 line 561）→ 见 3.2
- 批量删除（原 line 606）→ 见 3.2

**理由**：站点恢复是"当前状态变更"，不等于"历史上没死过"。死链证据应保留。

### 3.2 sites.js：删除站点时，死链站点走 upsert 而非删除

**改两处**：
- `worker/src/sites.js` 单站删除（原 line 561 附近）
- `worker/src/sites.js` 批量删除（原 line 606 附近）

**新逻辑**：
```
IF 被删除站点 enabled === 0（死链）:
  查找 dead_urls 是否有该 URL
  IF 存在:
    UPDATE dead_urls SET reason = reason || ' | site-deleted'
    —— 只追加删除痕迹，保留原始发现时间
  IF 不存在:
    INSERT INTO dead_urls (url, added_at, status, reason) VALUES (?, ?, 0, 'site-deleted')
ELSE:
  不做任何 dead_urls 操作
```

**注意**：当前 dead_urls 只有 3 列（url, added_at, status, reason），Phase 1 不扩列。

### 3.3 导入流程增加 dead_urls 感知

**前端 previewImport**：
- 加载 dead_urls 列表（admin 初始化时已有 deadUrls 状态）
- 对每条导入记录检查 URL 是否命中 dead_urls
- 命中项在预览区标注：`⚠️ 已知死链（added_at: X, reason: Y）`

**后端 /api/admin/sites/import**：
- 增加 `skipDead: boolean` 参数（默认 true）
- 导入时对每条记录：
  - 若 URL 在 dead_urls 中且 skipDead=true → 跳过，计入 skipped
  - 若管理员强制导入 → 正常创建/更新

**前端 doImport**：
- 增加复选框「跳过已知死链」（默认勾选）
- 若取消勾选，发送 skipDead: false

### 3.4 手动标记死链时写入 dead_urls

**改 setDeadByName**（worker/index.js）：
- 调用 /api/admin/sites/batch disable 成功后
- 额外调用 addDeadUrl(db, url, { reason: 'manual-marked' })
- 用 INSERT OR IGNORE，避免重复

**理由**：当前手动标记只改 enabled=0，不动 dead_urls，导致 dead_urls 与站点状态脱节。

## 四、数据流（Phase 1 最终态）

```
dead_urls（append-only 证据库）
  ├─ 写入来源：
  │   ├─ 手动标记死链（setDeadByName）→ reason='manual-marked'
  │   ├─ 站点删除且为死链 → reason='site-deleted'
  │   └─ 将来可扩展：cron/扫描（Phase 2）
  │
  ├─ 不删除（除非站点删除且为活链？不，彻底不删）
  │
  └─ 读取来源：
      ├─ 导入预览（previewImport）→ 跳过已知死链
      └─ 管理后台站点表 → 显示"已知死链"标记

sites.enabled（唯一状态轴）
  ├─ 恢复/启用 → 不改 dead_urls
  ├─ 删除（死链）→ upsert dead_urls
  ├─ 删除（活链）→ 不动 dead_urls
  └─ 导入 → 查 dead_urls，按策略跳过/强制

公开页
  └─ dead := enabled !== 1，死链折叠展示（已实现）
```

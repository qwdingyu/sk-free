# 17 · 首页全局分析与最优重构方案（PM + UI 设计师视角）

> 日期：2026-08-27
> 分析对象：`frontend/`（首页 SPA：`index.html` + `src/main.js` + `src/broadcast/*` + `src/styles.css`）
> 分析立场：专业产品经理 + UI 设计师，全局视角，目标是给出**一次到位的重构方向**，而非无止修补丁
> 前置阅读：`docs/08`（产品定位）、`docs/09`（前端信息架构）、`docs/15/16`（死链模型）

---

## 0. 一句话结论

首页**界面底子已经很好**（鲜度、死链可见、深/浅色、a11y、骨架屏都到位），问题不在 CSS，而在三处**全局性**缺陷：

1. **工程架构上有一枚定时炸弹**——`main.js` 是 `broadcast/*.js` 手工拼接的产物，而构建链不自动拼接。这是文档 08 当年点名的"双份代码靠手工同步"根因的**再次复现**，是用户最担心的"灾难"的精确形态。
2. **产品身份与价值主张不清晰**——首页有四个名字（README 的 "Sk-free API Broadcast"、`<title>` 的 "公益站导航"、`<h1>` 的 "TOKEN 站点速查"、域名 `free.eforge.xyz`），且 Hero 把"提交站点"（贡献者动作）当成主 CTA，消费者（来看哪个还能白嫖）的首屏引导是缺的。
3. **首页在"展示数据库"，没有"为护城河服务"**——本产品的护城河是**鲜度 + 可比性**（文档 08 结论），但首页把最值钱的信号（今天还有效吗 / 哪个额度最大）埋进了筛选栏和表格行，首屏没有"今日可信速览"。

**最优方案 = 先拆炸弹（Step 0）→ 再统一身份与 Hero（Step 1）→ 把护城河前置（Step 2）→ 收敛信息架构并建立渲染纪律（Step 3）→ 视觉收口（Step 4）。** 全程不引入新框架、不新增筛选维度，避免范围蔓延。

## 2. 先对齐赛道（否则分析会跑偏）

文档 08 已定调：这不是"导航站"，是**时效性羊毛情报聚合站**。其护城河只有两样：

- **鲜度**：用户敢信"这条今天还有效"；
- **可比性**：用户能一眼比出"哪个额度大、哪个不用魔法"。

任何首页改动都必须**放大这两件事**，而不是加功能。下面所有建议都以此为准绳。

---

## 3. 首页现状诊断（四层）

### 3.1 工程架构层 —— 🔴 P0 灾难风险（最该先处理）

**问题：双份真相 + 手工拼接，且构建不兜底。**
- `broadcast/*.js` 是源，`main.js` 是拼接产物，但 `npm run build` 不重新拼接。
- 开发者被注释引导去改 `broadcast/`，但只要没手动跑拼接脚本，改动在 `vite build` 后**静默丢失**。
- 这正是文档 08 所述"前端三份副本、反馈功能在复制环节整段丢失、根因未消除"的**同一模式的重演**。当前只是从 3 份变成 2 份，失败机制完全一样。

**次生症状（都是这枚炸弹的引信，不是独立 bug）：**
- `render()` 每次全量 `replaceChildren` 重建筛选栏 → 搜索丢焦点、高级面板被收起 → 被迫拆出 `applyFilterChange()` / `updateResultBar()` 打补丁（这是"没有渲染协调层"的典型气味）。
- `state` 是上帝对象，URL 同步 / 筛选 / UI / 抽屉状态全混在一起，每加一个功能就再长一截。
- 16 篇文档里大量"修死锁 / 修 NaN 排序 / 修焦点泄漏 / 修 tbody 嵌套"——都是对"全量 innerHTML 重建 + 手工监听器清理"这一结构的**局部修补**，结构本身没变。

> 不先拆这枚炸弹，后面每一次"优化首页"都是在会漂移的代码上叠补丁——这正是用户说的"造成灾难"。

### 3.2 产品 / 信息架构层 —— 🟠 P1

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| A | **主 CTA 错位**：Hero 里"提交站点"是贡献者动作，却被放在首屏主按钮位 | `index.html:36` 提交按钮与 `<h1>` 同行 | 消费者（来看站的人）首屏找不到"我该干什么" |
| B | **首页像数据库浏览器，不像决策助手** | 首屏 = 标题+1 行介绍 → 4 个数字 → 7 个预设 → 搜索 → 表格 | 没有"今日可信速览"这种能立刻建立信任与方向感的内容 |
| C | **信息架构偏重**：三层筛选 + 排序 + 视图切换 + 清除，对 ~18–68 条数据偏重 | `99-boot.js` 的 `renderFilters` | 筛选栏与列表争夺注意力；但结构化字段已让筛选有意义，重点在"收敛暴露面"而非删功能 |
| D | **"鲜度"作为护城河被低估** | 鲜度只有卡片/表格里的圆点 + 相对时间；首屏统计条是 收录/可签到/高额度/已失效 四个静态数 | 没有"我们每天都在验证"的信任叙事；死链可见性做得好但没被首屏放大 |

### 3.3 内容 / 文案层 —— 🟠 P1

- **四个名字**：README「Sk-free API Broadcast」/ `<title>`「sk-free 公益站导航」/ `<h1>`「TOKEN 站点速查」/ 域名 `free.eforge.xyz`。新访客 3 秒内不知道这是什么。
- `TOKEN` 是圈内黑话，对泛用户不友好；`<h1>` 应表达**用户收益**而非名词。
- `<intro>` 文案"收录可注册、可签到、可生图和长期备用的 API 站点"偏功能罗列，未说清"为什么信你"。

### 3.4 视觉 / 交互细节层 —— 🟡 P2（底子好，只收口）

- Hero 偏空：大块 teal 渐变但**没有视觉锚点**（无品牌标记、无一个 hero 级数据），与"落地页"应有的记忆点不匹配。
- 颜色语义冲突：`teal` 既是品牌色、**又是"高额度"档位色**；最高档没有从品牌 chrome 里独立出来。
- `h1 { white-space: nowrap }` 在文案变更时脆弱（目前宽度够，是隐患不是现 bug）。
- 默认表格视图合理（可比性是护城河），但移动端靠"隐藏列"降级，卡片视图更适合移动扫描——可考虑按视口自动选默认，而非只给手动切换。

### 3.5 必须保留的强项（🟢 不要动）

- **死链可见 + 沉底折叠**：传达"这个站在认真维护"，是信任资产，保留。
- **鲜度圆点 + 相对时间**：护城河的直接呈现，保留并放大。
- **档位配色（高=teal / 中=amber / 低=灰）**：可比性的视觉化，保留。
- **深/浅主题 + 跟随系统 + 降噪动效 + 骨架屏 + skip-link + 焦点陷阱**：a11y 质量高，保留。
- **详情抽屉（不跳页）**：保留。
- **结构化额度字段（quota_min/max/unit/tier/needs_proxy）**：文档 09 的地基已打好，UI 已受益，保留。

## 4. 最优方案（全局，非打补丁）

### Step 0 ｜ 消除"双份真相"——🔴 P0，防灾难（先做，约 0.5 天）

目标：让"改源码 → 构建 → 生效"成为**唯一路径**，消灭手工拼接。

**方案 A（推荐，最干净）：把 `main.js` 改回"真正的入口"，`import` 广播模块**
1. 给 `broadcast/*.js` 每个文件补 `export`（函数/常量导出），删除文件间通过全局作用域的隐式共享。
2. `main.js` 改为只做一件事：
   ```js
   import "./broadcast/00-config.js";
   import "./broadcast/10-state.js";
   // … 其余模块
   import "./broadcast/99-boot.js";
   ```
   （或直接 `import "./broadcast/99-boot.js"`，由 boot 再聚合；取决于导出方式）
3. **删除 `main.js` 里的拼接副本**，运行 `npm run build` 验证 `dist/main.js` 与旧产物行为一致。
4. 删掉那行"改 broadcast 再 build"的误导性注释。

**方案 B（最小改动）：保留拼接，但把拼接写进 `package.json` 的 `build`**
```json
"build": "node scripts/concat-broadcast.mjs && vite build"
```
并在 `scripts/` 新增 `concat-broadcast.mjs`（按序读取 11 个模块 → 写出 main.js）。
> 选 B 也能消除"忘记拼接"的坑，但仍是"生成物入库"，不如 A 彻底。

**验收**：改 `broadcast/80-view-card.js` 一行 → `npm run build` → `dist/main.js` 命中改动；删除 main.js 拼接副本后构建不报错。

---

### Step 1 ｜ 统一身份 + 价值主张型 Hero（🟠 P1，约 0.5 天）

- **定一个名字**。建议对外统一为 **「白嫖 API 速查」/ 英文保留 `sk-free`**，README、`<title>`、`<h1>`、域名描述全部对齐。
- **`<h1>` 讲用户收益**，不是名词：
  - 现：`TOKEN 站点速查`
  - 改：`今天还有哪些 AI API 能白嫖？`（副标题承载品牌名）
- **副标题讲信任（护城河）**：
  `每日验证 · 死链可见 · 额度横向可比`
- **主 CTA 让给消费者**：Hero 主按钮 = 「按今天能签到排序」或「直接看高额度」；"提交站点"降到工具栏/页脚的**次级按钮**（贡献是长尾动作，不该抢首屏）。
- **Hero 给一个视觉锚点**：放一个 hero 级数字，如「本日 38/68 站点已验证有效」，把"可信"一眼钉住。

---

### Step 2 ｜ 让首页"为护城河服务"：鲜度 / 可比性前置（🟠 P1，约 1 天）

在统计条与列表之间，新增一条 **「今日可信速览」**（这是首页从"数据库浏览器"变成"决策助手"的关键一跃）：

- 鲜度分布迷你条：24h 内 / 7 天内 / 陈旧 / 未验证 四段占比（用现有 `freshnessLevel` 直接算）。
- 两个动态信号：`今日新增/恢复 N 个` · `近 7 天变死链 M 个`。
- 一个**鲜度图例**（圆点颜色含义），让用户"看得懂颜色"，否则颜色再准也白搭。
- 保留"已失效（N）"折叠入口，并把"我们每天验证"做成一行信任注脚。

> 不新增字段、不新增接口——全部用现有 `sites[].verifiedAt / dead / quotaTier` 计算。

---

### Step 3 ｜ 收敛信息架构 + 建立渲染纪律（🟠 P1，约 1–1.5 天）

**IA 收敛（保留能力，收暴露面）：**
- 预设 chips（今天能签到 / 高额度 / 免费生图 / 无需魔法 / 一次性限免 / 无门槛）**就是产品的真实入口**，保留并作为首屏主导航。
- 搜索内联保留；"更多筛选"（档位/类型/能力/门槛/隐藏过期）**默认折叠**（现状已折叠，保持）。
- 排序 + 视图切换 + 清除 收到一条**安静的工具栏**，与列表拉开间距、降对比，不与列表抢视觉权重。
- **不新增任何筛选维度**——结构化字段已让现有筛选有意义，再加就是过度工程。

**渲染纪律（停止补丁循环的根治）：**
当前 `render()` 全量重建筛选栏是"搜索丢焦点"等补丁的根源。改为：
- 持久铬（Hero / 统计条 / 筛选栏外壳）**只构建一次**；
- 只有"列表区"和"结果计数/清除按钮"随交互更新（`updateResultBar` 已起步，扩成"列表区独立重渲"即可）；
- 模块间通过显式 `export` 通信（配合 Step 0 方案 A），不再依赖全局变量隐式共享。
> 这一步让后续加"死链库 Phase 2（文档 16）""死链投票"等功能时，不必再 carving 出新的 `applyXxxChange` 补丁函数。

---

### Step 4 ｜ 视觉收口（🟡 P2，约 0.5 天）

- 解决 `teal` 双义：高额度档位改用独立强调色（如琥珀已用于中档，高档可用品牌 teal 但加描边/星标区分），或高/中/低三档用**同一色相的不同明度阶梯**，与品牌 chrome 解耦。
- Hero 增加品牌标记 + 一个 hero 级数据锚点（见 Step 1）。
- `h1` 去掉 `white-space: nowrap`，改用语义换行 + `clamp()` 字号，文案变更不再撑破布局。
- 视图默认按视口智能选（桌面表格 / 移动卡片），手动切换保留。

## 5. 实施顺序与节奏（避免灾难的节奏）

| 顺序 | 步骤 | 工期 | 为什么这个顺序 |
|---|---|---|---|
| 1 | **Step 0 拆炸弹** | 0.5d | 不在干净的单源码上改，后面所有改动都会漂移 |
| 2 | Step 1 身份/Hero | 0.5d | 不动结构也能立刻提升首屏清晰度 |
| 3 | Step 3 渲染纪律（先） | 1d | 先让渲染可维护，Step 2 的新区块才好落地、不引新补丁 |
| 4 | Step 2 今日可信速览 | 1d | 在稳定渲染上叠加护城河前置 |
| 5 | Step 4 视觉收口 | 0.5d | 最后做，避免为会变的布局反复调样式 |

> 每一步都可独立验证、可回滚；不要在 Step 0 之前做任何"首页美化"——那是在炸弹上贴纸。

---

## 6. 明确**不做**的事（防止范围蔓延 / 防止灾难）

- ❌ 不引入新框架（React/Vue）。 vanilla + 显式导出 + 局部重渲足够，引入框架会放大双份代码风险。
- ❌ 不新增筛选维度 / 不新增字段。结构化字段已够，再加是过度工程。
- ❌ 不做"通用化框架"（文档 08 已判定为负收益）。本产品只需把"时效性情报"做深。
- ❌ 不重做死链模型——文档 15/16 已定，首页只需消费其输出（已失效计数 / 折叠）。
- ❌ 不把"提交站点"做成首屏主流程。贡献是长尾，消费才是主体。

---

## 7. 给老板的一句话

> 首页不丑，丑的是"它会悄悄不更新"。先把 `broadcast/*.js → main.js` 的手工拼接换成构建内自动 import（Step 0），其余的首页优化才不会被下一次构建吞掉。然后让首屏从"列数据库"变成"告诉我今天还能信哪个"——这就是这个产品唯一的护城河。

## 一、需求分析

### 1.1 当前项目的能力抽象

当前 sk-free 项目本质上是一个**信息收集与展示系统**：

```
用户提交 → 管理员审核 → 公开展示
    ↓            ↓
 URL 健康检查   管理后台 CRUD + 死链接管理
```

核心能力与具体业务解耦后：

| 能力 | 当前实现 | 通用化方向 |
|------|---------|-----------|
| 数据模型 | 站点（name/url/tags/...） | 可配置的字段 schema |
| 数据存储 | Cloudflare KV | 保持 KV（serverless 最优） |
| 用户提交 | POST /api/submit + 审核流 | 通用表单提交 + 审核流 |
| 管理后台 | 内嵌 HTML CRUD + 标签页 | 模板驱动生成 |
| 前端展示 | 卡片网格 + 投票 + 搜索 | 主题模板 + 配置驱动 |
| 认证 | Bearer Token | 保持（简单够用） |
| 速率限制 | IP 滑动窗口（用户+管理员） | 保持 |
| URL 健康检查 | checkUrlHealth + 死链接名单 | 数据质量保障 |
| 数据导入 | 智能 URL 解析 + 去重 + 死链接过滤 | CSV/JSON 导入 |

### 1.2 目标场景

10 分钟内上线一个类似项目，典型场景：

- 📚 **资源导航站**：AI 工具导航、设计资源导航、开源项目导航
- 📋 **信息收集表**：活动报名、问卷调查、反馈收集
- 🏷️ **目录/黄页**：公司目录、服务目录、人才库
- 📰 **内容聚合**：新闻聚合、博客聚合、论文列表
- 🎯 **产品展示**：产品目录、价格对比、功能矩阵

  "fields": [
    { "key": "name", "label": "名称", "type": "text", "required": true, "unique": true },
    { "key": "url", "label": "链接", "type": "url", "required": true, "healthCheck": true },
    { "key": "tags", "label": "标签", "type": "tags", "options": ["签到", "生图", "限免"] },
    { "key": "summary", "label": "简介", "type": "textarea", "max": 200 },

### 2.2 字段类型系统

| 类型 | 说明 | 表单控件 | 展示方式 |
|------|------|---------|---------|
| `text` | 单行文本 | `<input type="text">` | 纯文本 |
| `url` | 链接 | `<input type="url">` | 可点击链接 + 健康检查 |
| `textarea` | 多行文本 | `<textarea>` | 折叠/展开 |
| `number` | 数字 | `<input type="number">` | 格式化显示 |
| `tags` | 标签集 | 逗号分隔输入 / 多选 | 标签徽章 |
| `list` | 列表 | 每行一条 | 无序列表 |
| `select` | 单选 | `<select>` | 徽章 |
| `boolean` | 布尔 | 开关 | ✅/❌ |
| `date` | 日期 | `<input type="date">` | 相对时间 |
| `rating` | 评分 | 1-5 星 | 星级显示 |

```bash
# 方式一：命令行脚本（推荐）
npx create-infohub my-project \
  --name "AI 工具导航" \
  --template directory \
  --fields "name,url,tags,summary"

# 编辑 schema.json（唯一需要改的文件）

```

### 4.2 部署（一条命令）

```bash
# 部署 Worker + 上传 KV 数据
cd my-project
npx wrangler deploy

# 前端自动部署（GitHub Pages）
git push origin main
```

## 十、踩坑记录与最佳实践

### 10.1 模板字面量中的转义陷阱

在 Cloudflare Worker 的模板字面量中生成 HTML 时，必须注意：

| 场景 | 错误做法 | 正确做法 |
|------|---------|---------|
| 内联 onclick + 动态参数 | `onclick="fn('${x}')"` | `data-value="${esc(x)}"` + 事件委托 |
| JS 字符串中的 `\n` | `"\n"` (模板中) | `"\\n"` (输出正确的 `\n`) |
| innerHTML 插入用户数据 | `el.innerHTML = t` | `el.innerHTML = esc(t)` |

**核心教训**：模板字面量 → HTML → JS 属性是 3 层转义链，永远用 `data-*` + 事件委托。

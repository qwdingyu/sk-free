# 06 通用信息收集与展示平台方案

> 日期：2026-08-24
> 状态：方案设计（待评审）
> 目标：10 分钟上线一个类似的"收集 → 审核 → 展示"站点

## 一、需求分析

### 1.1 当前项目的能力抽象

当前 sk-free 项目本质上是一个**信息收集与展示系统**：

```
用户提交 → 管理员审核 → 公开展示
                ↓
         管理后台 CRUD
```

核心能力与具体业务解耦后：

| 能力 | 当前实现 | 通用化方向 |
|------|---------|-----------|
| 数据模型 | 站点（name/url/tags/...） | 可配置的字段 schema |
| 数据存储 | Cloudflare KV | 保持 KV（serverless 最优） |
| 用户提交 | POST /api/submit | 通用表单提交 + 审核流 |
| 管理后台 | 内嵌 HTML CRUD | 模板驱动生成 |
| 前端展示 | 卡片网格 | 主题模板 + 配置驱动 |
| 认证 | Bearer Token | 保持（简单够用） |
| 速率限制 | IP 滑动窗口 | 保持 |

### 1.2 目标场景

10 分钟内上线一个类似项目，典型场景：

- 📚 **资源导航站**：AI 工具导航、设计资源导航、开源项目导航
- 📋 **信息收集表**：活动报名、问卷调查、反馈收集
- 🏷️ **目录/黄页**：公司目录、服务目录、人才库
- 📰 **内容聚合**：新闻聚合、博客聚合、论文列表
- 🎯 **产品展示**：产品目录、价格对比、功能矩阵

### 1.3 行业最佳实践参考

| 项目 | 架构 | 可借鉴点 |
|------|------|---------|
| **Cabinet** (getwitless) | Cloudflare Workers + KV | 零依赖、单文件部署 |
| **Pages CMS** | Next.js + Git CMS | Schema 驱动、Git 即数据库 |
| **TinaCMS** | 文件驱动 CMS | 内容模型定义 |
| **Notion API** | API-first 数据库 | 灵活的属性系统 |
| **Airtable** | 表格即应用 | 字段类型、视图、自动化 |

## 二、架构设计

### 2.1 核心理念：Schema 即配置

整个平台的行为由一个 `schema.json` 文件决定，无需修改代码：

```json
{
  "name": "AI 工具导航",
  "description": "收录可注册、可签到的 AI API 站点",
  "fields": [
    { "key": "name", "label": "名称", "type": "text", "required": true, "unique": true },
    { "key": "url", "label": "链接", "type": "url", "required": true },
    { "key": "tags", "label": "标签", "type": "tags", "options": ["签到", "生图", "限免"] },
    { "key": "summary", "label": "简介", "type": "textarea", "max": 200 },
    { "key": "checkin", "label": "签到额度", "type": "text" },
    { "key": "models", "label": "支持模型", "type": "text" },
    { "key": "rate", "label": "倍率", "type": "text" },
    { "key": "register", "label": "注册方式", "type": "text" },
    { "key": "notes", "label": "备注", "type": "list" }
  ],
  "tags": ["签到", "生图", "DC系", "半DC", "非DC", "限免", "抽奖"],
  "display": {
    "layout": "grid",
    "columns": 3,
    "sortBy": "default",
    "priorityTags": ["全部", "签到", "生图", "限免"]
  },
  "submit": {
    "enabled": true,
    "rateLimit": { "max": 5, "window": "24h" },
    "fields": ["name", "url", "tags", "summary"]
  },
  "theme": {
    "primary": "#087f78",
    "accent": "#b8e35a",
    "style": "minimal"
  }
}
```

### 2.2 字段类型系统

| 类型 | 说明 | 表单控件 | 展示方式 |
|------|------|---------|---------|
| `text` | 单行文本 | `<input type="text">` | 纯文本 |
| `url` | 链接 | `<input type="url">` | 可点击链接 |
| `textarea` | 多行文本 | `<textarea>` | 折叠/展开 |
| `number` | 数字 | `<input type="number">` | 格式化显示 |
| `tags` | 标签集 | 逗号分隔输入 / 多选 | 标签徽章 |
| `list` | 列表 | 每行一条 | 无序列表 |
| `select` | 单选 | `<select>` | 徽章 |
| `boolean` | 布尔 | 开关 | ✅/❌ |
| `date` | 日期 | `<input type="date">` | 相对时间 |
| `rating` | 评分 | 1-5 星 | 星级显示 |

## 三、10 分钟上线流程

### 3.1 一键初始化（零代码）

```bash
# 方式一：命令行脚本（推荐）
npx create-infohub my-project \
  --name "AI 工具导航" \
  --template directory \
  --fields "name,url,tags,summary"

# 方式二：直接复制 + 修改 schema
cp -r templates/directory my-project
cd my-project
# 编辑 schema.json（唯一需要改的文件）
vim schema.json
```

### 3.2 部署（一条命令）

```bash
# 部署 Worker + 上传 KV 数据
cd my-project
npx wrangler deploy

# 前端自动部署（GitHub Pages）
git push origin main
```

### 3.3 时间分解

| 步骤 | 耗时 | 说明 |
|------|------|------|
| 1. 定义 schema | 3 分钟 | 填写字段名、类型、标签 |
| 2. 填充初始数据 | 2 分钟 | 粘贴 JSON 或 CSV |
| 3. 部署 Worker | 1 分钟 | `npx wrangler deploy` |
| 4. 部署前端 | 1 分钟 | `git push` |
| 5. 配置域名 | 3 分钟 | CNAME 或 workers.dev |
| **总计** | **~10 分钟** | |


## 六、技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 存储 | Cloudflare KV | Serverless、全球边缘、免费额度足够 |
| 计算 | Cloudflare Workers | 零运维、冷启动快、免费 |
| 前端 | 原生 JS + CSS | 零依赖、加载快、易定制 |
| 认证 | Bearer Token | 简单够用、无第三方依赖 |
| 部署 | Wrangler + GitHub Actions | 一键部署、自动 CI/CD |
| Schema 格式 | JSON | 人类可读、工具支持好 |
